# 营养报告后端迁移说明

## 2026-09-08：机器初稿替换为运动员V2.0规则

当前自动评价不再调用旧的固定食物分类区间、固定能量/钙阈值或女性EER评价。
旧配置与私有辅助方法仅保留兼容参考，不参与当前报告及预览。
实际摄入量计算和人工复核流程保留；PDF新增专项页，Excel新增“运动员专项评价”表。

- 参数文件：`config/athlete_intervention_v2.json`，来源为用户提供的《运动员膳食干预参数V2.0》。
- `user.athleteType`：`strength`、`team`、`endurance`；未选择时只按配置中的项目名称精确匹配。
- `user.trainingPhase`：`training`时才应用规则；未填写时仅识别明确的“正常训练/训练期”等当前状态。赛期、其他或未知阶段不评价。
- 体重须为有效正数（kg），缺失不计算蛋白质/碳水目标；年龄缺失不计算钙目标。
- 成年分界暂按18岁实现，是待业务确认的实现假设，原文未写明；已在报告中明确提示。
- 约5/7 g/kg的碳水为参考点，不划定合格区间；有氧蛋白质只比较下限；钙和蔬菜不判断过量。
- 脂肪供能比分母与原三大营养素图一致：蛋白质×4+碳水×4+脂肪×9，分母为0时不评价。
- 文档未给出总能量及其他食物类别标准，显示未提供标准，不沿用旧结论。
- `athlete_evaluation.rows`保留参考目标、差值、机器初稿与人工最终评价。建议为审核初稿，不是临床处方。
- 手动评价支持新增`proteinEvaluation`、`carbohydrateEvaluation`、`fatEvaluation`；空字符串表示不计算/清除评价。

验证：`python -m unittest discover -s tests -p "test_athlete*.py" -v`及原营养报告测试。
以下迁移说明中的旧评价方式仅描述历史实现。

本目录从只读源项目 `D:\project\python\营养\vue-project\vue-project` 迁移而来。源项目未修改；没有复制其 `node_modules/`、`dist/`、`.venv/`、`output/`、压缩包、IDE 配置或 Vue 源码。

## 迁移内容

- `nutrition.py`：原 `services/nutrition_service.py` 的营养计算、分类评价、女性 EER 和手动评价逻辑；资源路径改为包内绝对路径，并显式返回未匹配食物。
- `builders/pdf.py`：原 PDF 构建逻辑；三大营养素供能占比使用 PDF 原生矢量饼图，修复硬编码工作目录、固定临时文件名及并发覆盖问题，支持环境变量 `NUTRITION_REPORT_FONT` 指定中文字体，并在 PDF 中展示人员、日期和 OCR 换算告警。
- `builders/excel.py`：原五张营养分析工作表，并新增 `OCR换算说明` 工作表。
- `config/`、`data/food_db.json`：报告计算配置和食物营养数据；当前紧凑 PDF 不嵌入食物照片，营养素占比图以矢量方式绘制。
- `adapter.py`：新增 OCR 食物频率问卷到原报告 `user + meals` 模型的自动适配。
- `service.py`：不依赖 Flask/FastAPI 的纯 Python 门面，可由当前 `local_service.py` 直接导入。

## 原项目输入模型

原报告服务接收：

```json
{
  "user": {
    "name": "张三",
    "age": 22,
    "height": 168,
    "weight": 55,
    "gender": "female",
    "activityLevel": "2"
  },
  "date": "2026-07-21",
  "meals": [
    {"name": "米饭", "amount": 300}
  ],
  "autoEvaluation": true
}
```

`meals[].amount` 是日摄入克数。原后端把同名食物合并后，以 `food_db.json` 的每 100g 数据计算能量、蛋白质、脂肪、碳水化合物和钙；再按 `nutrition_template.json` 评价食物类别与钙，女性且年龄/PAL 完整时按 `female_energy_eer.json` 评价能量。

## OCR 数据自动换算

当前 OCR 的单人结构来自 `local_service.py`：

```python
person = {
    "id": "ocr/1",
    "general": {"姓名": "张三", "调查日期": "2026-07-01"},
    "food_rows": [{
        "食物名称": "米饭",
        "平均每次食用量": "100g",
        "次数": "2",
        "频率周期(请核对)": "每天",
        "是否不吃": ""
    }]
}
```

适配器按下式折算日均克数：

- 每天：`每次克数 × 次数`
- 每周：`每次克数 × 次数 ÷ 7`
- 每月：`每次克数 × 次数 ÷ 30`
- 每年：`每次克数 × 次数 ÷ 365`
- 不吃：0，不进入营养计算

只可靠换算克、千克；毫升按 `1 ml≈1 g` 估算并产生告警。份、个、勺等没有重量依据的单位不猜测，不进入营养值。区间用中点估算并告警。原食物数据库没有覆盖全部 38 个固定问卷项目，`FOOD_REFERENCE_MAP` 对缺项使用明确的同类代表食物，并在导出的 PDF/Excel 留下 `proxy_food_reference` 告警，不能把该估算当作精确食物成分分析。

## 纯 Python 调用

```python

result = generate_pdf_from_ocr_person(

        "gender": "female",

```

## 2026-10-12 新增标准与批量导出

计算入口为 `NutritionService.build_report_data`，逐项规则为 `food_standard_evaluation`；页面预览、单人PDF/Excel、批量导出复用同一计算。

- 坚果≥10g；豆类（含豆制品）主食能量占比≥5%；薯类≥15%。谷类上限为100%−5%−15%=80%：≤80%为达标，>80%为超过；没有提供谷类下限，不把低于80%判为不足。缺失记录/分母为0仍不可判断。
- 奶类≥400g鲜奶等价量。奶粉/奶酪：克数×本品蛋白质(g/100g)÷同一营养库鲜奶蛋白质(g/100g)。鲜奶/酸奶按原重。营养总计仍按实际食物计算；不得再次加入等价鲜奶。
- 鸡蛋每个50g；蛋类≥50g。水产品/(水产品+畜禽肉)重量≥30%；畜禽肉为肉类扣除水产品后的部分，包含禽肉，不再提示需要区分禽肉与畜肉；未提供肉类总量阈值，畜禽肉评价用短横杠。
- 水果200–500g。蔬菜最低400g，与V2全局或运动类型的 `vegetables_g_min` 取较高值；采用最低量标准，不以原先500g封顶。
- 肉（含水产品）蛋奶蛋白质/全部记录食物蛋白质≥50%；零食评价统一“建议尽量不吃”，不计分；饮料、酒类评价统一为ASCII短横杠 `-`。
- 基础适用体重60–70kg。超过70kg时克数目标须由专业人员确认 `foodTargetScale >= 1`；比例不变。低于60kg或缺体重不自动外推。新食物标准不沿用旧V2“仅训练期”的限制；原V2宏量营养素/钙规则仍保留其训练期适用范围。
- 分值只是10条定量规则的0/1达标计数，不是经验证的临床风险评分。谷类上限依赖豆类和薯类下限，不是独立风险指标。已完成问卷中的空白摄入按未食用处理；非空但无法换算的记录不计为0摄入，只有10项可判断时才显示完整达标率。定性项不参与分母。无OCR追溯信息的直接 `meals` 调用视为调用方提交了完整记录，须由调用方保证覆盖；工作台OCR路径按已完成问卷处理空白，同时保留非空异常的换算原因。
- 克数和能量占比判定先使用未舍入值，展示时再四舍五入。部分食物仍使用代表食物估算，报告保留警示。
- 整体建议用最多一位小数展示（不改变计算精度）；合并重复提醒。PDF建议独立整行标题、全宽逐条排列、续行悬挂缩进，数值与单位不可拆行。预览/导出保留原机器评价文案与短横杠，不再自动转换为其他词语；人工覆盖仍保留。

批量接口：`POST /nutrition/jobs/{job_id}/reports/batch`，format 为 pdf / excel / both。默认当前任务全部人员，可提交同一任务完整人员列表以包含未保存的核对修改；拒绝子集、重复或外来ID。
按人传 `profiles` 和 `reviews`，前端仅传人工相对最近机器初稿的差异，避免把旧机器结果当成人工覆盖。每次批量使用同一营养库快照。ZIP 中每人一个PDF和/或Excel，并包含 `manifest.json` 和 `导出清单.txt`；单人失败不阻断其他人，全部失败也有明确清单。无可换算食物的人员不生成误导性空报告。
范围是当前任务全部人员，不是其他历史任务；历史任务混合导出及跨任务去重未实现。报告补充信息和人工评价仍是当前页面状态，刷新前应导出；本次没有扩展其跨刷新持久化。

验证：`python -m unittest discover -s tests`；`node --test tests/nutrition-batch.test.mjs`；`npm run build`。

## 2026-10-15 评价顺序与对外展示

- 总能量或碳水不足：主食相关项先提示不足，鼓励补足总量，不按谷类结构占比要求减量。总蛋白质不足时优先补充肉、奶、蛋等来源，达标后才评价结构；缺失信息不推断为不足。
- 肉类（含水产品）新增当前量、参考目标及缺口。肉类蛋白参考量=max(总蛋白下限-谷类蛋白-奶类蛋白-蛋类蛋白,0)，再按当前肉类加权蛋白密度换算食物克数；无可用肉类密度时明确标注以牛肉估算。其他食物蛋白另计，不机械把此估算缺口当作必须追加量。
- 专项评价的内部占比仅用于计算；前端预览、PDF与Excel均投影为克数，显示最多两位小数。钙保留原mg单位。谷豆薯按当前类别加权能量密度折算，无当前类别时内部使用代表食物；水产品按肉类重量折算，优质蛋白按蛋白质克数、脂肪按宏量供能折算。百分比规则不出现在专项页。
- PDF说明页默认不生成；食物频率设置增加开关`includeQualityPage`，保存至浏览器。请求字段`include_quality_page`用于单人及批量导出；Excel保留OCR审计工作表。
- 专项页右下角使用亚洲上海时区的真实生成日期，独立于调查日期。人工最终评价和原始OCR记录保留。
