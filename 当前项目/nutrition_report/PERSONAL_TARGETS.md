# 个人目标与报告核查（2026-10-19）

## 计算顺序（2026-10-20确认）

1. **个人参数 → 营养需求**：蛋白质、碳水按运动类型×体重，脂肪按既定个人能量参考20–30%÷9。需求上下限不随实际食量变化，换算程序也不得改写需求。
2. **营养需求 → 分项默认食物等价克数**：用户确认可采用当前营养库/API的默认食物每100g营养密度：谷类米饭、豆类豆腐、薯类土豆、畜禽肉牛肉、水产品海白虾。固定奶蛋果蔬坚果目标沿用原规则。默认食物缺少有效必要参数时明确不可换算，不静默换成别的食物。
3. 各固定类别营养贡献先计入一次；剩余碳水和蛋白质联立换算，不能把全部碳水都分给米饭后又重复加豆薯奶果，也不能从需求中扣实际过量饮食反推目标。既定豆/薯/谷5/15/80主食能量分配及水产/畜禽30/70重量分配作为默认换算端点，不另建第二套个人需求。
4. 换算量加回营养库贡献后，碳水应等于个人目标，蛋白质应处于个人范围内；个人优选蛋白质计划点保持原值，因既有优质蛋白约束形成的换算点单独保留算式记录，不篡改个人需求。此换算不是完整推荐食谱，不再对其中脂肪另作个人摄入评价或产生脂肪缺口/补油提醒。
5. **真实记录 → 实际营养/同口径等价量 → 比较**：谷豆薯按本类实际碳水÷默认食物每克碳水换算；畜禽及水产按本类实际蛋白质÷默认食物每克蛋白质换算。原记录重量另行保留；表格与建议明确标注默认食物等价量，不能用混合生熟食物的原重与默认食物目标直接比较。奶类保留原鲜奶等价换算，但不再显示“按蛋白质估计”。
6. 所有评价和增减建议复用同一行目标、实际值、边界；脂肪只比较**真实脂肪摄入**与个人脂肪需求。无额外菜单或烹调用油假设。

### 换算式与量纲

令固定奶、蛋、果蔬、坚果的碳水和蛋白质贡献分别为 `F_C/F_P`；各主食按既定能量分配、默认食物每克营养密度折算出的每kcal碳水/蛋白质系数为 `S_C/S_P`；70%牛肉+30%海白虾每克碳水/蛋白质系数为 `M_C/M_P`。求主食能量 `E`、内部肉类换算总重 `G`：

```
S_C * E + M_C * G = C_need - F_C
S_P * E + M_P * G = P_conversion - F_P
```

谷豆薯的目标克数为 `E * 类别能量份额 / 默认食物每克能量`；畜禽/水产目标为 `0.7G/0.3G`。内部总重仅用于联立换算，不输出额外“肉类合计”评价或建议。

例如米饭每100g碳水25.9g，换算式是 `分给谷类的碳水克数 / 0.259`。不是总碳水需求全部÷0.259再另加其他来源。米饭等价重量不是生米重量，食物克数也不能直接与营养素克数相加。

## 能量与规范边界

总能量参考优先使用填写的静息代谢区间。2026-10-20起，足球、篮球正常训练期按实际体重叠加运动净消耗（周净消耗÷7），且不再另乘PAL；其他项目、伤病康复、非训练期保留原参考并提示未应用课表。缺少BMR时沿用EER，绝不在EER上再次加运动消耗。**不门控或覆盖主食评价**；蛋白质、碳水目标不变，脂肪20–30%供能随新能量参考更新。原填写BMR和实际摄入不改写，身高资料保留，不伪造系数。

### 分项目训练消耗（计划估算）

1 MET≈3.5 mL·kg⁻¹·min⁻¹；gross=MET×3.5×kg÷200×min，net=(MET−1)×3.5×kg÷200×min。叠加静息代谢必须用net，不能用gross。此参考不是完整全天总消耗，未包括日常非训练活动和食物热效应；不是实测能量需求或唯一食谱。

- 足球：每周6次×120分钟，整堂平均5–8 MET；每周一次专项体能已包含，不额外叠加。60kg时gross=3780–6048、net=3024–5292 kcal/周。150分钟方案可将weeklyMinutes改为900：gross=4725–7560、net=3780–6615。
- 篮球：周一至五每天180–210分钟，周六360–390分钟，总1260–1440分钟；每周2–3次×24–60分钟力量（48–180分钟）包含在总时长中。专项5–8 MET，力量3.5–6 MET。联合枚举时长及MET端点，不能把力量重复加到总训练时间。60kg时net=5008.5–10483.2 kcal/周。示例weeklyMinutes=1350,strengthMinutes=90,sportMET=6,strengthMET=4.5，专项1260分钟，gross=8363.25，net=6945.75 kcal/周（日均992.25）。示例点不是默认范围中点。
- 体操：等待训练计划，不借用足球或篮球方案。未匹配项目也不猜测。

API `user.trainingPlan`可覆盖`weeklyMinutes`、`strengthMinutes`、`sportMET`、`strengthMET`，接受有限非负数或有序二元区间；MET至少1。每周力量不得超过总分钟下限。OCR general中“训练计划”对象或“每周训练总分钟”“每周力量分钟”可传递个人实际出勤，0保留为休训，留空采用项目默认；课表随个体变化时必须更新。输出`nutrition.energy.reference_type=bmr_plus_net`，同时保留`resting_bounds`及`training_expenditure`的gross/net、日均、时长、公式、假设和来源。

## 17条独立建议

固定顺序：能量、蛋白质、碳水、脂肪、钙、谷类、豆类、薯类、奶类、蛋类、畜禽肉、水产品、水果、蔬菜、坚果、零食、肉蛋奶优质蛋白。谷豆薯不合并，畜禽肉和水产品不合并、不另加肉类合计。第一条仍只写能量状态；数据核查提醒单独显示。

## 自动核查

报告生成前检查计算边界、最终评价、主食与碳水方向冲突、肉类零目标、非有限/负数、计划规范冲突及极端摄入。达到参考值3倍或单项食物超过3000g/天是**工程复核触发条件，不是医学上限**，不据此认定录入必错，更不自动改写摄入量。

机器建议冲突可按个人目标重建，并保留纠正记录。人工结论、人工建议和空白保持原样；发现冲突只提醒复核。无法匹配/换算条目仍沿用已批准的逐行忽略并留痕规则；缺少营养参数仍阻断完整评价。

PDF两种样式、Excel评估页和浏览器预览均展示核查提醒。批量ZIP名称按当前实际导出份数生成；缺少问卷者只在清单说明，不伪造报告。
