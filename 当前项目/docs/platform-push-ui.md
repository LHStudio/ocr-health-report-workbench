# 页面一键上传到运动员平台

影像、食物营养、体检化验的核对区域各有独立的“一键上传到平台”按钮。**只有点击后发送，不会随 OCR 完成自动推送。** 上传当前任务全部人员的点击时快照（包括尚未点击保存的字段修改），不是当前筛选或分页。按钮不修改原始文件或下载格式，也不代替“保存核对/下载”。

- 影像只上传姓名、性别、年龄、超声所见、超声诊断、检查时间；Excel 仍为原有九列。
- 化验使用标准检验录入模板字段，只取当前任务人员的 review_fields，不扫描模板中的历史人员。
- 营养使用现有生成报告流程与 Excel→接口适配器，保留当前个人档案和人工评价；发送报告 JSON 而非 PDF 或原始问卷。无可换算食物的人员不发送。
- 完整日期可规范化为 YYYY-MM-DD；缺失或不能确定具体日的日期不会自动补值。历史批次人工指定的日期不作为新任务默认值。
- 平台按人员身份和日期处理，可能更新已存在的同日报告；请先核对姓名、日期和内容。此接口不会新建运动员。

## 服务端配置

默认平台为 `https://athlete.f8q8.com/api`。密钥仅由后端读取；不要写入前端、浏览器本地存储或提交 Git。

优先读取运行后端进程的环境变量 `SURVEY_BASE_URL`、`SURVEY_OPEN_TOKEN`。也可创建本机私有文件：

Windows：`%LOCALAPPDATA%/OCRHealthWorkbench/platform-push/config.json`

其他系统：`~/.local/share/OCRHealthWorkbench/platform-push/config.json`

```json
{"base_url":"https://athlete.f8q8.com/api","token":"填写已授权的平台密钥"}
```

限制该目录为当前操作系统账户访问。这个目录不得映射到 Web 静态目录、Git 或共享网盘。文件配置每次请求读取，无需重启；环境变量需随后端启动生效。配置后刷新页面。GET `/platform-push/config` 只返回配置状态与平台地址，不返回密钥。服务须保持本机回环地址绑定，不应未经身份鉴权直接暴露到公网。

## 状态、重试与中断

POST `/platform-push/{imaging|nutrition|lab}/{job_id}` 接收当前页面快照，立即返回 202；后台处理，GET 同一路径查询逐人结果。点击返回丢失时前端只查状态，不自动再次 POST。

所有推送共享私有目录排他锁。`registry.json` 按目标接口、姓名、日期保存结果和 payload SHA256。已成功的相同数据跨任务、跨正常重启不重复发送；修改后的数据在明确点击后可更新。此前命令行批量推送的审计目录不自动导入此注册表。

营养去重比较时仅忽略“营养库查询时间”和“报告生成日期”这两个自动时间戳，完整发送内容与其原始哈希仍留存。营养素、食物、人工评价等实际内容变化仍需上传；缺少调查日期的人员会被列为待核对，不使用当天日期代填。

- **成功**：HTTP200、code0，且姓名、日期、人员/报告 ID 和 created 回执契约全部匹配。
- **明确失败**：HTTP401 或 HTTP200/code1。查看原因，修正平台资料/密钥后点击“重试明确失败项”。该按钮仍跳过已成功的相同数据。
- **待核对**：日期、模板或报告内容校验失败；修正页面数据后重新点击上传。合格记录可继续处理。
- **回执不明**：超时、重定向、其他错误或不匹配回执。暂停本批后续发送；相同人员/日期即使修改内容也禁止盲目重发。

私有目录 `runs/<id>/` 包含快照、推送 payload 和状态；`registry.json` 含回执。它们包含健康数据，不可提交 Git。进程异常退出后保留 `push.lock`，状态显示中断。管理员必须先核对平台及回执，再备份审计，明确解决 registry 中 sending/uncertain 项，最后移除锁；禁止仅删锁/清空目录后重新上传。应用不提供不安全的“一键忽略不明结果”。

本地代码回滚不能撤销已被远端平台接收的数据；平台数据修正必须另行核实授权。
