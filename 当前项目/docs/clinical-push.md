# 影像与检验数据独立推送

影像页面、一键导入及 Excel 下载/导出保持原来的完整字段与核对流程。平台原九列（病人ID、文件名、姓名、性别、年龄、超声所见、超声诊断、检查时间、需核对字段）不删减；历史七列文件也可直接读取。**仅 API 推送内容**限制为姓名、性别、年龄、超声所见、超声诊断、检查时间六个字段。

`scripts/push_clinical_reports.py` 只读取指定 XLSX，不修改源文件、不重新计算检验值、不创建运动员。默认预检，显式传入 `--commit` 才发送。接口分别为 `/open/imaging` 和 `/open/lab`；支持已确认的 HTTPS 根地址或 `/api` 前缀。凭证仅从 `SURVEY_OPEN_TOKEN` 环境变量读取，不写入代码、命令行、日志或版本库。

```powershell
$env:SURVEY_BASE_URL = 'https://your-platform.example/api'
$env:SURVEY_OPEN_TOKEN = '<平台开放接口凭证>'
python scripts/push_clinical_reports.py --input '<原始影像导出.xlsx>' --kind imaging --audit-dir '<私有审计目录>'
python scripts/push_clinical_reports.py --input '<原始影像导出.xlsx>' --kind imaging --audit-dir '<私有审计目录>' --commit
python scripts/push_clinical_reports.py --input '<检验批量录入表.xlsx>' --kind lab --audit-dir '<另一私有审计目录>' --commit
```

检验读取第二行表头，跳过只有序号的空模板行，保留病历号前导零、数值、等级和区间原文。仅将病历号的 Excel 文本常量公式 `="..."` 提取为文本；拒绝其他未计算公式。

影像按表头匹配六个业务字段，兼容原七列、平台九列及已有六列文件，支持列顺序变化，拒绝缺失/重复/未知表头。仅发送六字段中有值的字段，不发送文件名、病人ID或核对列；空值仍保留缺失，不补造。源文件只读。

完整日期支持中文年月日、点/斜线/横线、全角数字和空格、Excel日期/序列值（遵循工作簿日期系统）及时间戳。仅在发送的 JSON 内统一为 `YYYY-MM-DD`，不改原始表格列或报告文字。缺失日期、月级日期或日为0均拒绝并记录到 `rejected.json`，**不会自动补为当月1日**；其他合格行继续。需从原报告确认具体日期后在私有副本中补录，并保留源文件哈希、原行号、姓名、证据路径及页码。不得使用出生日期、末次月经或病人ID猜测检查日期，不得把相似姓名强行对应。

接口按精确姓名匹配，重名须由人工确认出生日期后处理。本脚本不会自动改名或补出生日期。同一运动员同一天的报告可能被接口覆盖，远端写入不属于源码回滚范围。

每条发送前保存 `sending` 检查点；只有 HTTP200、整数 `code=0`、姓名/日期、运动员ID/报告ID和 created 标记均符合才计成功。401停止批次；重定向、超时、未知HTTP和不匹配回执记为不确定并停止，不盲目重发。相同输入与审计目录再次执行跳过已有记录，包括失败和不确定结果。补推须人工核对后以仅包含待处理记录的独立输入执行，不得删除检查点绕过保护。

退出码0为全部通过，2为部分成功/缺失/拒绝，1为配置或文件错误。`preflight.json`、`checkpoint.json`、`summary.json` 和 `payloads/` 含健康数据，仅保存在本地私有目录，不提交Git。

## 自动推送状态

营养、检验、影像均未挂接识别/报告生成后的自动推送。营养已有独立推送脚本，检验与影像本次新增独立推送脚本。识别完成不会自行向平台发送。若后续需要自动化，应另行接入明确开关、人工核对门槛、状态队列及失败处理，不能把 OCR 完成等同于可安全发送。
